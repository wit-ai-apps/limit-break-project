# CORTEX EDU 基本構想 SSOT v1.0

- 決定日時: 2026-07-31 JST
- 状態: `APPROVED_CONCEPT`
- 親構想: CORTEX APP GROUP 2026-07-31 14:55 JST版
- MVP対象: 中学2年数学・一次関数
- 対象リポジトリ: CORTEX Limit Break

## 1. 目的

CORTEX EDUは、小学校から大学、資格、入社試験、社会人の再学習まで、学習者の許可の下で学習情報を継続的に管理する教育データプラットフォームである。

LIMIT BREAKはCORTEX EDUの情報を利用し、日々の課題、提出、採点、復習、個別学習を実行する最初の主要アプリである。

```text
CORTEX FOUNDATION
        ↓
CORTEX EDU
        ↓
LIMIT BREAK / Edu bc / NoteLink / LexiTrainer
```

共通理念:

> AIはユーザを評価するためではなく、ユーザの成長を支えるために存在する。

## 2. 用語と責任範囲

| 名称 | 種別 | 責任範囲 |
|---|---|---|
| CORTEX APP GROUP | プロダクトグループ | 全体ブランドと共通思想 |
| CORTEX FOUNDATION | 共通基盤 | Identity、権限、監査、SSOT、AI連携 |
| CORTEX EDU | 教育プラットフォーム | 学習者、技能、教材、成績、生涯学習履歴 |
| LIMIT BREAK | ユーザ向けアプリ | 課題、提出、採点、復習、日々の学習実行 |
| Edu bc | 教材入力アプリ | 活字教材の解析と構造化 |
| Submission Scan | LIMIT BREAKモジュール | 手書き答案の取込と問題別分割 |
| NoteLink | 入出力プロダクト | 紙・手書きとCORTEX EDUの接続 |
| LexiTrainer | 特化アプリ | 語彙・英語技能トレーニング |
| AIユイ先生 | EDU共通AIサービス | 生徒・保護者・講師への学習支援 |

`CORTEX EDU`を単一の巨大な利用者向けアプリにはしない。利用者はLIMIT BREAK等のアプリを通してEDUの機能を利用する。

## 3. 学習者Identity

「生涯学習者ID」は思想として採用するが、外部へ永久固定IDを公開しない。

```text
内部 learnerId（UUID）
├─ 既存STU_ID
├─ 組織内生徒ID
├─ 本人アカウント
├─ 保護者アカウント
├─ 学校・塾の在籍情報
└─ ID統合・分離履歴
```

初期要件:

- learnerIdはCORTEX EDU内部UUIDとする
- 組織別IDとの対応を別管理する
- 重複統合と誤統合解除を可能にする
- 未成年から成人への管理主体移行を想定する
- アカウント回復と本人確認の履歴を残す
- 世界共通IDよりデータエクスポートとポータビリティを優先する

## 4. 組織境界とアクセス制御

正式成績と生涯学習情報を追加する前に、以下をP0として実装する。

```text
認証済み
＋同一組織
＋有効な在籍・担当関係
＋対象データへの権限
＋本人・保護者の公開設定
```

必須事項:

- 通常講師は担当外生徒を閲覧・更新できない
- 学校・塾は自組織で生成した正式記録を管理する
- 本人の生涯技能履歴と組織の正式成績を分離する
- 重要な閲覧・訂正・確定・出力を監査ログへ記録する
- サーバー処理でも組織・担当・公開範囲を毎回検証する

## 5. 技能モデル

技能は教材横断の共通軸として扱う。

```text
教科
→ 学年・科目
→ 分野
→ 単元
→ 小単元
→ 技能
→ 誤答段階
```

最初から全教科・全年齢を定義しない。MVPでは中学2年数学・一次関数に限定する。

技能定義には次を持たせる。

```text
skillCode
skillVersion
status
replacedBy
curriculumReference
prerequisiteSkillCodes
```

問題には一つ以上の技能と、途中段階ごとの採点観点を対応させる。

## 6. 誤答モデル

誤答を二軸で記録する。

1. 何ができなかったか: 学年、教科、分野、単元、小単元、技能、途中段階
2. どのようにできなかったか: 知識、理解、手順、適用、計算、読解、表現、時間

一回の誤答だけで弱点を確定しない。

```text
誤答観測
→ 弱点候補
→ 異なる類題で再確認
→ 弱点確定
→ 練習中
→ 翌日・3日後・7日後の確認
→ 定着
```

## 7. 教材と権利状態

教材原本と、教材から抽出した構造・技能情報を分離する。

### 原本保存可能

- 講師・組織の自作教材
- CORTEX EDU独自問題
- 著作権切れ・適法な公開教材
- 権利者から許諾を得た教材

### 原本保存を原則行わない

- 市販教材
- 学校教科書
- 権利状態を確認できない第三者教材

後者では、原則として次の索引情報を管理する。

- 書誌情報、出版社、版
- ページ、大問、小問
- 単元、技能、難易度、目安時間
- 生徒が所有教材を開くための指示

OCR、原文保存、画面表示、課題配信を同じ許可として扱わない。教材ごとに権利情報と許可範囲を記録する。具体的な運用は教材契約と専門家確認を前提とする。

## 8. 二つのスキャン

```text
CORTEX Scan Core
├─ Edu bc
│  └─ 活字教材、数式、図、目次、問題構造の解析
└─ Submission Scan
   └─ 手書き答案、消し跡、解答領域、複数ページの解析
```

撮影、台形補正、回転補正、画質判定、保存は共通化できる。OCRモデル、レイアウト解析、データ形式、保存期間、処理後の用途は分離する。

## 9. 課題と個別出題

講師はページ、大問、小問、全問、奇数・偶数、A・B問題、問題数、学習時間を組み合わせて指定できる。

初期の個別化は「共通問題＋個別問題」とする。

```text
授業内容
＋過去の弱点
＋忘却防止
＋理解確認
＋予習・挑戦
```

講師が全生徒の問題を毎回確認する方式にはしない。指定方針内は自動配信候補とし、範囲外、未習、権利不明、大幅な難易度変更等の例外だけ講師確認へ回す。

## 10. 採点と正式成績

二つのAIの一致は、正しさの十分条件ではない。

```text
AI1判定
＋AI2判定
＋画像品質
＋問題形式
＋正答・採点基準
＋過去の講師確定データ
        ↓
仮採点
        ↓
講師確定
        ↓
正式成績・技能習熟度
```

MVP初期は講師確定を必須とする。講師確定答案を蓄積し、問題形式別の正確率、AI一致時の正確率、修正率を測定した後に限定的な自動確定へ進む。

## 11. 実装状態の語彙

機能状態を単一の「実装済み」で表現しない。

| 状態 | 意味 |
|---|---|
| PROPOSED | 構想・提案 |
| DESIGNED | 設計済み |
| REPORTED_IMPLEMENTED | 実装済みとの報告 |
| CODE_VERIFIED | コード確認済み |
| UI_VERIFIED | 実画面確認済み |
| TEST_VERIFIED | テスト確認済み |
| YUI_APPROVED | ユイ承認済み |
| USER_GO | ユーザ承認済み |
| PRODUCTION | 公開運用中 |

複数状態を併記できるものとする。

## 12. 縦型MVP

対象:

- 教科: 中学2年数学
- 単元: 一次関数
- 教材: 自作・独自問題を基本
- 市販教材: 書誌情報、ページ、問題番号、技能索引を基本

一本通す処理:

```text
講師が課題を作成
↓
生徒別に配信
↓
答案提出
↓
AI仮採点
↓
講師確定
↓
誤答技能・誤り方を記録
↓
技能習熟度を更新
↓
翌日・3日後・7日後に再出題
```

## 13. 実装フェーズ

### Phase 0

用語、責任範囲、SSOT、検証状態台帳。

### Phase 1（P0）

組織境界、生徒アクセス権限、閲覧履歴、監査ログ。

### Phase 2

既存STU_IDと内部learnerIdの対応、統合・分離・エクスポート設計。

### Phase 3

中学2年数学・一次関数の技能コードMVP。

### Phase 4

教材登録、ページ・問題・技能の対応。

### Phase 5

課題作成、生徒別配信、問題単位答案。

### Phase 6

AI仮採点、講師確定、訂正履歴。

### Phase 7

技能別習熟度、復習、再出題。

### Phase 8

学校・塾テスト、通知表、模試。

### Phase 9

進路、資格、生涯学習ポートフォリオ。

## 14. 非目標

現MVPでは以下を行わない。

- 世界共通学習者ID
- 全教科・全年齢の技能体系完成
- 市販教材原本の共通配布
- AI一致だけによる正式成績の自動確定
- CORTEX APP GROUP全製品の認証統合
- 学校・塾・資格試験を単一尺度で単純比較

## 15. 変更管理

本SSOTの決定事項を変更する場合は、変更理由、影響範囲、移行方法、承認者、決定日時を記録する。技能コード、学習者ID、正式成績、教材権利、アクセス権限に関する破壊的変更は、既存データの移行計画なしに行わない。
